# Stego Finder: หาของที่คนอื่นซ่อนไว้

SweetHide ซ่อนข้อมูลแบบเข้ารหัสและกระจายตำแหน่ง จึงแทบไม่ทิ้งร่องรอยให้จับได้ แต่รูปที่เพื่อนส่งมาท้า หรือโจทย์ CTF ส่วนใหญ่ใช้เครื่องมือง่าย ๆ ที่ทิ้งร่องรอยไว้เต็มไปหมด Stego Finder คือชุดเครื่องมือที่ไล่หาร่องรอยพวกนั้นให้ในครั้งเดียว ทั้งในรูปภาพและไฟล์เสียง WAV

ทุกอย่างในนี้ **อ่านไฟล์อย่างเดียว** ไม่แก้ไขไฟล์ต้นฉบับ และไม่เขียนอะไรลงดิสก์เอง ถ้าเจออะไรที่ดึงออกมาได้ จะส่งข้อมูลกลับไปพร้อมชื่อไฟล์ที่แนะนำ ให้ผู้ใช้เป็นคนกดบันทึกเอง

> ตอนนี้ Stego Finder เป็นไลบรารี `SweetHide.Forensics` ที่พร้อมใช้งานแล้ว แต่ยังไม่ได้ต่อเข้ากับ CLI และแอป Windows กำลังจะตามมาเร็ว ๆ นี้

## ใช้งานยังไง

เรียกครั้งเดียว ได้รายการสิ่งที่น่าสงสัยเรียงจากมั่นใจมากไปน้อย

```csharp
var report = new StegoFinder().AnalyzeFile("suspect.png");
foreach (var finding in report.Findings)
{
    Console.WriteLine($"{finding.Confidence:P0}  {finding.Title}: {finding.Detail}");
}
```

ถ้าอยากได้เป็น JSON ใช้ `JsonSerializer.Serialize(report, ForensicsJsonContext.Default.StegoFinderReport)` ได้เลย ข้อมูลที่ดึงออกมา (`Payload`) จะไม่ถูกใส่ลงใน JSON เพราะบางทีใหญ่เป็นเมกะไบต์ แต่จะมีขนาดและชื่อไฟล์ที่แนะนำบอกไว้

แต่ละ finding มีค่าความมั่นใจ (`Confidence`) ตั้งแต่ 0 ถึง 1 อ่านคร่าว ๆ ได้แบบนี้

| ค่า | ความหมาย |
|---|---|
| 0.9 ขึ้นไป | เกือบแน่นอนว่ามีคนตั้งใจซ่อนไว้ เช่น เจอ `flag{...}` หรือมีไฟล์ ZIP ต่อท้ายรูป |
| 0.5–0.9 | น่าสงสัย ควรเปิดดู |
| ต่ำกว่า 0.5 | เป็นข้อสังเกต เช่น ข้อมูลกล้อง หรือสถิติที่ยังไม่ชัด |

ถ้ามีการตรวจไหนทำไม่สำเร็จ เช่นรูปเสียจน decode ไม่ได้ ข้อผิดพลาดจะอยู่ใน `Errors` แต่การตรวจอื่น ๆ ยังทำต่อจนจบ

## ตรวจอะไรบ้าง

### 1. ไล่ LSB ทุกแบบ (แบบ zsteg)

เครื่องมือซ่อนข้อมูลส่วนใหญ่เอาข้อมูลไปเขียนทับบิตต่ำ ๆ ของพิกเซลตรง ๆ Stego Finder จะลองอ่านทุกแบบที่เป็นไปได้ คือบิต 0–7, channel R, G, B, A, RGB, BGR, RGBA, ARGB, อ่านพิกเซลตามแถวหรือตามคอลัมน์, และเรียงบิตแบบ MSB หรือ LSB ก่อน รวมแล้ว 256 แบบ แต่ละแบบอ่านแค่ 4 KiB แรก รูป 12 ล้านพิกเซลจึงใช้เวลาไม่ถึงวินาที

ของที่อ่านออกมาจะถูกให้คะแนนว่าเป็นอะไร

- ข้อความที่อ่านได้ (นับภาษาไทยเป็นข้อความด้วย)
- ไฟล์ที่รู้จักจาก magic bytes เช่น PNG, JPEG, GIF, ZIP, PDF, 7z, RAR, gzip, ELF, EXE, BMP, WAV, OGG, MP3, SQLite
- ข้อมูลที่ขึ้นต้นด้วยความยาว 32 บิต (big- หรือ little-endian) แล้วตามด้วยข้อมูลยาวเท่านั้นพอดี
- รูปแบบ `ความยาว:ข้อความ` ของไลบรารี Stegano
- ข้อความที่จบด้วย NUL หรือตัวคั่นยอดนิยมจาก tutorial อย่าง `$t3g0`, `#####`, `*^*^*` หรือบิต `1111111111111110`

ลายซ้ำ ๆ ที่เกิดจากพื้นสีเรียบ เช่น `UUUUUUUU` จะถูกหักคะแนนทิ้ง จะได้ไม่เตือนมั่ว

### 2. Metadata

อ่านข้อความทุกที่ที่ metadata ซ่อนได้ ได้แก่ PNG `tEXt`, `zTXt`, `iTXt`, `eXIf`, JPEG comment, EXIF (คำอธิบายภาพ, ชื่อช่างภาพ, ลิขสิทธิ์, UserComment, XPComment ฯลฯ), พิกัด GPS, XMP, GIF comment และ WebP EXIF/XMP รวมถึง LIST/INFO ในไฟล์ WAV

ช่องที่ผิดปกติจะถูกทำเครื่องหมายไว้ เช่น ยาวผิดปกติ มีข้อมูลไบนารีในช่องที่ควรเป็นข้อความ มีข้อความแอบต่อหลัง NUL ในแท็ก EXIF มีคอมเมนต์ XML ซ่อนใน XMP หรือมีข้อความอยู่ใน APP segment แปลก ๆ ของ JPEG

### 3. โครงสร้างไฟล์และข้อมูลต่อท้าย

- ไล่ chunk ของ PNG พร้อมเช็ก CRC ทุก chunk และบอกว่า chunk ไหนเป็นแบบที่ไม่รู้จักหรือเป็น private chunk
- ไล่ segment ของ JPEG, block ของ GIF, chunk ของ WebP/WAV และส่วนหัวของ BMP
- หาข้อมูลที่แอบต่อท้ายหลัง PNG `IEND`, JPEG `EOI`, GIF trailer, ขนาด RIFF หรือหลังพิกเซลของ BMP (ท่ายอดฮิตคือเอาไฟล์ ZIP ไปต่อท้ายรูป)
- สแกนหา signature ของไฟล์อื่นทั้งไฟล์แบบ binwalk พร้อมประมาณขนาด เพื่อตัดออกมาเป็นไฟล์ได้พอดี
- ถ้า CRC ของ `IHDR` ไม่ตรง จะลองหาความกว้างหรือความสูงที่ทำให้ CRC ตรง ซึ่งแก้ท่า "แก้ความสูงของรูปให้ซ่อนครึ่งล่าง" ได้ในพริบตา

### 4. Strings

เหมือนคำสั่ง `strings` แต่หาได้ทั้ง ASCII, UTF-8 (รวมภาษาไทย) และ UTF-16LE พร้อมบอกตำแหน่งในไฟล์ Stego Finder ใช้ตัวนี้หาข้อความหน้าตาเหมือน flag เช่น `flag{...}`, `CTF{...}`, `picoCTF{...}` แต่จะไม่สนข้อความมั่ว ๆ ที่บังเอิญอยู่ในข้อมูลพิกเซลที่ถูกบีบอัด

### 5. ถอดรหัสข้อความต่อกันเป็นทอด (แบบ CyberChef)

ข้อความที่เจอจากทุกที่จะถูกลองถอดด้วย Base64, Base64url, Base32, hex, เลขฐานสอง, ตัวเลขทศนิยมคั่นด้วยช่องว่าง, URL encoding, รหัสมอร์ส, ROT13 และ ROT47 ถ้าผลที่ได้ยังอ่านได้ก็ถอดต่อไปเรื่อย ๆ (สูงสุด 6 ชั้น) และบอกลำดับการถอดให้ เช่น `Base32 → Hex → Base64`

### 6. QR code และบาร์โค้ด

อ่าน QR, Data Matrix, Aztec, PDF417 และบาร์โค้ด 1D ด้วย ZXing.Net ทั้งจากรูปตามที่ตาเห็น และจากภาพ bit plane ของแต่ละ channel ด้วย เพราะ QR ที่ซ่อนไว้ในบิตต่ำสุดจะมองด้วยตาไม่เห็นเลย รูปเล็กจะถูกตรวจทุก plane ส่วนรูปใหญ่จะตรวจบิต 0 ของทุก channel ก่อน เพื่อไม่ให้รอนานเกินไป

### 7. ฟิลเตอร์ภาพ (แบบ StegSolve)

สำหรับ UI ที่อยากให้ผู้ใช้ส่องเอง มีฟังก์ชันสร้างภาพใหม่ ได้แก่ bit plane ของแต่ละ channel, bit plane รวม, ดูทีละ channel, XOR/ลบ/บวกภาพสองภาพ, ยืดคอนทราสต์, histogram equalisation, random colour map, เอา alpha ออก (เห็นสีที่ซ่อนใต้พิกเซลโปร่งใส), gray bits และกลับสี

### 8. เทียบสองภาพ

ถ้ามีทั้งรูปต้นฉบับและรูปที่ถูกแก้ จะบอกได้ว่าพิกเซลเปลี่ยนไปกี่จุด อยู่ตรงไหน มีภาพ heatmap ให้ดู และดึงบิตต่ำสุดเฉพาะตำแหน่งที่เปลี่ยนออกมาให้ลองอ่าน

### 9. Steganalysis เชิงสถิติ

- **Chi-square** (ใช้ตัวเดียวกับในหน้าวิเคราะห์ของ SweetHide)
- **RS analysis** และ **Sample Pair Analysis** ประมาณว่ามีกี่เปอร์เซ็นต์ของพิกเซลที่ถูกเขียนทับ แยกตาม channel
- **แผนที่ความสุ่มของ LSB** แบ่งภาพเป็นบล็อก แล้วดูว่าบล็อกไหนบิตต่ำสุดสุ่มผิดปกติเมื่อเทียบกับบิตถัดไป ช่วยชี้ว่าข้อมูลซ่อนอยู่ตรงไหนของภาพ

Chi-square อย่างเดียวชอบเตือนผิดกับภาพที่ไล่สีเรียบ ๆ Stego Finder จึงให้น้ำหนักกับมันก็ต่อเมื่อ RS หรือ SPA เห็นด้วย

### 10. ไฟล์เสียง WAV

รองรับ PCM 8 และ 16 บิต ทั้ง mono และ stereo ไล่อ่านบิตต่ำของ sample แบบเดียวกับรูป (ทุก sample, เฉพาะช่องซ้าย หรือเฉพาะช่องขวา) และวาด spectrogram ออกมาเป็นรูป PNG เพราะการเขียนตัวหนังสือหรือรูปไว้ในย่านความถี่เป็นโจทย์ CTF คลาสสิกที่การตรวจแบบไบต์ต่อไบต์ไม่มีทางเจอ ต้องเปิดดูด้วยตาเท่านั้น

## ข้อจำกัดที่รู้อยู่แล้ว

- ไล่ LSB ทีละบิตเท่านั้น ยังไม่รองรับการอ่านหลายบิตต่อ channel พร้อมกัน (แบบ `b2` ของ zsteg) หรือการอ่านพิกเซลย้อนกลับ
- ตรวจการซ่อนแบบที่เครื่องมืออื่นใช้ได้ดี แต่ **ตรวจ SweetHide เองไม่ได้** เพราะ SweetHide เข้ารหัส กระจายตำแหน่งด้วยรหัสผ่าน และใช้ LSB matching ซึ่ง chi-square, RS และ SPA ไม่ได้ออกแบบมาจับ
- ไม่ได้วิเคราะห์ DCT coefficient ของ JPEG จึงจับเครื่องมืออย่าง steghide, outguess หรือ F5 ไม่ได้ และไม่มีการเดารหัสผ่านให้
- ค่าประมาณจาก RS และ SPA คลาดเคลื่อนได้ราว ±10% และเชื่อถือไม่ได้เมื่อเกือบทั้งภาพถูกเขียนทับ
- GIF ที่เป็นภาพเคลื่อนไหว ตรวจพิกเซลแค่เฟรมแรก
- WAV รองรับเฉพาะ PCM 8/16 บิต mono/stereo ไฟล์ที่ใหญ่เกิน 256 MiB จะไม่ถูกตรวจ (ปรับได้ใน `StegoFinderOptions`)

## ความปลอดภัย

ไฟล์ที่เอามาตรวจถือว่าเป็นของอันตรายเสมอ parser ทุกตัวเขียนเองและเช็กขอบเขตทุกครั้ง ไม่เชื่อค่าความยาวที่ไฟล์บอก ถ้าไฟล์อ้างว่ามีข้อมูล 4 GiB ก็จะไม่จองหน่วยความจำตามนั้น การคลายบีบอัด zlib มีเพดานกันระเบิด XML ห้าม DTD และไม่โหลดอะไรจากภายนอก มีเทสต์ที่ตัดไฟล์ทุกตำแหน่งและสุ่มทำไฟล์เสียหายเพื่อยืนยันว่าไม่มีอะไรพัง

ข้อมูลที่ดึงออกมาจากไฟล์ก็เชื่อไม่ได้เหมือนกัน ชื่อไฟล์ที่แนะนำควรผ่าน `SafeFileName` ก่อนบันทึก และไม่ควรเปิดหรือรันไฟล์ที่ดึงออกมาโดยอัตโนมัติ
